# 글쓰기 규칙

보고서는 읽히려고 쓴다. 독자는 바쁘고, 첫 화면에서 판단한다.

## 1. 구조

- **결론 먼저.** 첫 절에 숫자 타일 2~4개와 3줄 이내 요약. 정책·화면 설계 문서는 셀 수 있는 숫자가 없으면 타일을 지운다. 숫자를 지어내지 않는다(모르는 값은 `[확인 필요]`). 요약 줄은 모든 종류가 같은 순서: ① 판단(되나·안 되나, 일정 정상·주의·위험) ② 근거가 되는 가장 큰 결과나 문제(수치) ③ 다음 할 일과 독자에게 필요한 것(결정·도움·기한).
- **절 하나에 메시지 하나.** 절 제목만 이어 읽어도 보고서 줄거리가 나와야 한다.
- **표가 기본.** 같은 모양의 항목이 3개 이상이면 표로. 산문은 표로 담기지 않는 판단·이유에만.
- **배경·과정은 짧게.** "어떻게 했나"보다 "무엇이 됐나". 과정이 중요하면 부록 절로 뺀다.
- **부록 허용.** 세부 근거·전체 목록은 마지막 절 "부록"으로 보내고 본문에는 요지만. 제목을 "부록"으로 시작하면 web 레이아웃에서 접힌다.
- **선택 절.** 틀에서 제목 끝에 "(없으면 지움)"이 붙은 절은 내용이 없으면 절째 지운다. 남겨 두면 check.py 가 오류로 잡는다.
- **흐름은 단계 블록으로.** "A → B → C" 대신 `:::steps`. 대외 문서는 화살표가 금지다.

## 2. 분량 (check.py 기준값과 같다)

| 대상 | 상한 |
|---|---|
| 결론 절 산문 | 450자, 항목 5개 |
| 절 하나 산문(표·블록 제외) | 700자 권장, 1,200자 넘으면 오류. 정책·화면 설계는 `###` 소단위마다 센다 |
| 문서 전체 산문 | 6,000자 권장 |
| 본문 보이는 글자(표·상자·카드 포함, 부록 절 제외) | 종류별: 진행·완료 4,500 · 장애 4,000 · 제안·분석 7,000 · QA 9,000 · 정책 16,000 · 설계 20,000 |
| 본문 표 행(부록 절 제외) | 종류별: 진행·완료 45 · 장애 40 · 제안·분석 70 · QA 90 · 정책 170 · 설계 200 |
| 문장 하나 | 110자 |
| 절마다 굵게 | 4곳 |

## 3. 문장

- 한 문장에 한 뜻. 주어와 결론을 앞에.
- **말투는 두 가지만 쓴다.**

| 자리 | 말투 | 예 |
|---|---|---|
| 목록·표 칸·결론 줄·결함 카드 | 개조식 명사형 | "결함 4건 모두 수정 완료", "기존 버전 유지", "담당 지정 필요" |
| 이어지는 문장(해석 문단, 대외 안내) | 합쇼체 | "처리를 막는 결함 2건을 고쳐 다시 확인했습니다." |

- **평서형 "~했다·~한다·~였다"는 쓰지 않는다.** 메모·일기 말투라 보고서에서는 퉁명스럽게 읽힌다(check.py 경고).
- 명사형은 "~함", "~음"보다 "완료", "필요", "유지", "확인"처럼 명사로 끝내는 쪽이 짧고 자연스럽다.
- 수치에는 기준을 붙인다: 어느 서버·판, 언제, 무엇 대비. "빨라졌다" 대신 "86초 → 0.05초(스테이징, 10/5)".
- 모르는 것은 `[확인 필요: 무엇]`. 추정은 "추정"이라고 쓰고 근거를 단다.
- 내부 약어·코드명은 처음 나올 때 풀어 쓴다. 대외 문서에는 쓰지 않는다.

## 4. 쓰지 않는 표현 (check.py 가 센다)

화면 문구·인용은 따옴표나 `코드`로 감싸면 이 검사에서 빠진다(components.md "검사에서 빠지는 글자").

| 표현 | 대신 |
|---|---|
| ~를 통해 | 로, 해서 |
| 다양한, 효율적으로, 효과적으로 | 무엇이 몇 개, 수치 |
| 중요합니다, 중요한 역할 | 왜 중요한지 사실 한 줄 |
| ~라고 할 수 있습니다, ~것으로 보입니다 | 근거와 함께 단정, 또는 "추정" |
| 다음과 같습니다, 살펴보겠습니다 | 바로 내용 |
| 결론적으로, 요약하자면 | 결론 절이 따로 있으니 삭제 |
| 뿐만 아니라, 또한(문두) | 문장 분리 |
| 최적화, 고도화, 극대화, 혁신 | 실제로 바뀐 것 |
| 긴 대시(—) | 쉼표, 괄호, 문장 분리 |
| 이모지 | 상태 딱지(표 칸에 "통과", "실패" 등). ★ ○ △ ✓ 같은 글자 기호는 범례로 써도 된다 |

## 5. 판단을 요청할 때 (proposal)

- 독자가 실제로 골라야 하는 것만 "결정할 것" 절에 모은다. 진행만 하면 되는 항목에는 선택지를 달지 않는다.
- 결정 항목마다: 제안 1개, 다른 선택지(있을 때만), 차이(비용·위험), 기한.
- 상대가 고를 필요 없는 것을 묻지 않는다. 기본 제안을 적고 "다르면 알려 달라".
- 상대에게 무례하게 읽히는 문장 금지: "회신이 없으면 제안대로 진행합니다" 대신 "기한까지 회신 부탁드립니다. 제안대로 괜찮으면 확인만 주셔도 됩니다".

## 6. 대외(external) 문서

- 경로, 파일 이름, 커밋, PR 번호, 서버 주소, 내부 코드명, 담당자 실명(합의된 경우 외) 금지.
- 화살표(→, ▶)와 절 기호(§) 금지. 기간은 "86초에서 0.05초로".
- 내부 판단·내부 일정·내부 갈등은 넣지 않는다.
- 상대 조직의 약점(보안 취약점 등)은 "정리 예정"처럼 쓰고 세부는 따로 전달한다.
