# 원고 문법

원고는 마크다운이다. 아래 블록만 추가로 쓴다. HTML·style 은 쓰지 않는다.

## front matter

```
---
title: 주문 화면 개편 시험 결과            # 내용이 보이는 제목
type: qa                                    # progress·completion·qa·proposal·analysis·incident·policy·spec
audience: internal                          # internal·external
date: 2026-10-05
author: 플랫폼팀
basis: 스테이징 · v1.4.2 · 10/5 오전        # 수치의 기준
layout: doc                                 # doc(기본)·web. 아래 "레이아웃"
evidence: code                              # QA 만, 캡처 없이 코드로 검수했을 때(references/qa.md)
label: 화면설계서                           # 머리 표시를 바꿀 때(기본은 종류 이름)
numbering: off                              # 절 자동 번호 끄기(화면 번호를 그대로 쓰는 문서)
footer: (쓰면 HTML 맨 아래에 한 줄. 생략하면 없음)
---
```

값 뒤에 두 칸 이상 띄우고 `# ` 로 시작하는 글은 설명 주석으로 보고 버린다.

| type | 머리 표시 | 쓰는 곳 |
|---|---|---|
| progress | 진행 보고 | 주간·월간 진행 |
| completion | 완료 보고 | 끝난 일의 결과 |
| qa | QA 보고 | 시험·검수 결과, 결함 |
| proposal | 제안 | 상대가 골라야 할 것이 있을 때 |
| analysis | 분석 보고 | 자료를 보고 판단 |
| incident | 장애 보고 | 장애 경과·재발 방지 |
| policy | 정책 | 규칙·권한·결정을 정해 두는 문서 |
| spec | 화면 설계 | 화면설계서·스토리보드·화면 모음 |

## 레이아웃

- `layout: doc`(기본): 화면에서도 A4 한 장처럼 보이는 한 단. PDF 와 모양이 같다.
- `layout: web`: 1100px 이상 화면에서 넓은 캔버스(최대 1280px), 왼쪽에 따라오는 목차(지금 읽는 절 표시), 결론 절은 큰 숫자 첫 화면, 연달아 놓인 강조 상자·차트는 두 단, `부록`으로 시작하는 절은 접힌다. 그보다 좁은 화면은 doc 과 같다.
- 인쇄·PDF 는 layout 과 관계없이 늘 doc 모양의 A4 다. 접힌 부록도 펼쳐서 찍힌다.
- 고르는 기준: 화면으로 돌려 읽는 긴 분석·대시보드성 보고는 web, 출력·첨부가 주인 문서는 doc.

## 절

`## 제목` 으로 나눈다. 번호는 빌드가 붙인다(원고에 번호를 써도 지운다, `numbering: off` 면 번호 없음). 첫 절은 결론으로 강조된다. `### 소제목` 은 절 안에서만. 목차에는 `##` 만 나온다.

제목이 길어 목차가 길어지면 ` | ` 뒤에 목차용 짧은 이름을 쓴다. 본문 제목에는 앞부분만 나온다.

```
## 오후 주문이 하루 늦게 도착하는 원인은 출고 마감 시각 | 지연 원인
```

## 숫자 타일

```
:::tiles
3.2초 → 0.4초 | 주문 목록 첫 화면(스테이징) | ok
2건 | 남은 결함 | warn
:::
```
`값 | 설명 | 색`. 색은 ok·warn·bad·info 중 하나 또는 생략. 2~4개.

## 상태 딱지

표에서 **머리글에 상태·결과·판정·진행·평가 중 하나가 들어간 열**의 칸만 딱지가 된다. 칸 글자가 아래 단어와 같거나, 단어 뒤에 괄호·가운뎃점·쉼표로 덧붙인 경우("완료 (10/6)")에 붙는다. 다른 열(규칙·내용·비고 등)에서 "보류", "적용"을 낱말로 써도 딱지가 되지 않는다.

| 색 | 단어 |
|---|---|
| ok | 통과, 완료, 해결, 정상, 적용, 반영, 켜져 있음, 유지, 확인됨, 성공, 수리, 수정 완료, 변경 불요 |
| warn | 진행, 진행 중, 보류, 주의, 지연, 부분, 확인 필요, 예정, 재현 안 됨, 검토, 대기, 재검수, 검수 중, 미배정, 미정, 다음 판, 수정 중 |
| bad | 실패, 미해결, 문제, 위험, 중단, 오류, 차단, 누락 |
| info | 정보, 참고, 결정, 결정 필요, 제안, 해당 없음 |

결함 카드 머리의 상태도 같은 단어를 쓴다. 정렬은 열 단위다: 비어 있지 않은 칸의 과반이 숫자(단위 하나까지, "31초"·"49쪽")인 열은 머리글까지 전부 오른쪽 정렬되고, 그렇지 않은 열은 숫자 칸이 있어도 왼쪽 정렬이다. 첫 열이 전부 20자 이하(이름 열)이면 첫 열을 굵게, 문장이 섞이면 보통 굵기로 둔다.

## 빈칸 표시

`[확인 필요: 무엇]` 은 본문·표 칸·카드 어디에 있어도 노란 표시로 남는다. `check.py` 는 front matter 까지 세어 GAP 으로 알린다.

## 강조 상자

```
:::callout warn
한두 문장. 문서당 1~2개만.
:::
```
연달아 놓은 상자는 web 넓은 화면에서 두 단으로 놓인다. 색 뒤에 제목을 쓸 수 있다: `:::callout warn 예외: 결제 취소된 주문`(스토리보드의 예외 상자).

## 캡처 묶음

![주문 목록 · 결제 후](shots/order_after.png)

설명은 "화면 이름 · 상태"로. 이미지는 HTML 안에 들어가고, 큰 캡처는 자동으로 줄어든다. 누르면 크게 보인다.
본문 중간 한 장은 일반 마크다운 `![설명](경로)` 도 된다. SVG 파일도 그대로 들어간다(흐름도·구성도는 래스터로 바꾸지 말고 SVG 로).

한 줄에 놓을 장 수는 `:::shots 1`·`:::shots 2`·`:::shots 3` 으로 정한다. 생략하면 화면 폭에 맞추고, PDF 에서는 두 장씩(화면 설계 문서는 한 장씩) 놓는다. 넓은 캡처는 `:::shots 1` 로 둬야 글자가 읽힌다.

## 결함 카드 (QA)

```
:::defect D-01 | 결제 완료 뒤 주문 목록 미갱신 | 해결
관찰: 실제로 본 것 그대로
기대: 원래 그래야 하는 것과 근거
증거: ![결제 완료 뒤 주문 목록](shots/order_list.png)
조치: 고친 내용·담당
:::
```
- 칸이 되는 키는 관찰·기대·증거·조치·원인·재현·추정 일곱 개뿐이다. 다른 줄은 ":" 가 있어도 앞 칸에 이어 붙는다.
- 관찰·기대·증거는 필수(check.py 가 확인). 상태는 딱지 단어 중 하나.
- 증거는 캡처, 인라인 코드(`` `파일:줄` ``), 펜스 코드 블록 모두 된다. 펜스 코드는 키 다음 줄부터 쓴다.

````
증거: `auth-policy.ts:184` 의 정규식
```
^/terms-evidence/(upload-jobs|jobs)(/|$)
```
````

## 막대 그래프

```
:::bars 화면 진입 시간(초, 스테이징)
주문 목록 | 0.4 | ok
주문 상세 | 0.6 | ok
정산 내역 | 2.1 | warn
:::
```
`라벨 | 값 | 색`. 막대 길이는 값 칸의 **첫 숫자**로 정하고, 값 칸 글자는 그대로 보인다("17~33" 은 17 길이로 그리고 "17~33" 으로 표시). 제목에 단위와 기준을 쓴다.

## 차트

```
:::chart line 메일 대기열 건수(10분 단위, 10/2)
19:10 | 120
19:20 | 640
19:40 | 1,284 | bad
20:00 | 0
:::
```
- 종류: `bar`(세로 막대, 항목 비교) · `line`(시간 흐름) · `donut`(전체 중 비중, 6개 이하). 항목 순위만 보이면 되면 `:::bars` 가 더 짧다.
- 줄 형식은 막대 그래프와 같다(`라벨 | 값 [| 색]`). 색을 준 점·막대만 강조된다. 도넛은 색을 안 주면 정해진 순서의 구분색을 쓴다.
- 축 눈금은 값에서 자동으로 고른다. 제목에 단위·기준을 쓴다. 밝은·어두운 화면 모두 테마 색을 따른다.
- 연달아 놓은 차트는 web 넓은 화면과 PDF 에서 두 단으로 놓인다.

## 흐름 단계

```
:::steps 문서 반영 흐름
올리기 | 파일을 끌어 놓음
자동 확인 | 형식·중복 확인
적용 | 서비스에 반영
:::
```
`단계 | 한 줄 설명`(설명 생략 가능). 번호와 잇는 선은 빌드가 그린다. 5단계 이하·짧은 설명이면 가로, 그보다 길면 세로로 놓인다(좁은 화면은 늘 세로). 대외 문서에서 금지된 화살표(→) 흐름 대신 쓴다.

## 화면 카드 (spec)

화면설계서의 화면 하나:

```
:::screen 화면 7 | 상품 상세 | 데이터 수급 관리
하는 일: 상품 하나의 세 문서 상태와 남은 일을 보고 직전 버전으로 되돌린다
![상품 상세 · 문서 세 줄](shots/s07.png)
| 요소 | 보여 주는 것 | 누르면 |
|---|---|---|
| 문서 줄 | 서비스 중 버전 · 교체 후보 · 남은 일 | 버전을 누르면 원문 |
| 되돌리기 | 직전 버전이 있을 때만 | 확인 창 |
메모: 시안이라 다른 상품은 열리지 않음
:::
```

- 머리: `번호 | 화면 이름 | 메뉴`(메뉴 생략 가능, 번호 없이 이름만도 됨). 번호는 쓴 그대로 보인다.
- 차례: 머리, 하는 일 한 줄, 그림(여러 장 가능), 요소 표, 메모. 요소 표가 세 열이면 폭이 22% · 39% · 39% 로 고정된다.
- 화면 모음(예시집)처럼 표 없이 `보이는 것:`·`누르면:`·`규칙:`·`권한:`·`비고:` 칸을 쓰면, 넓은 화면에서 그림 왼쪽·설명 오른쪽으로 놓인다.
- PDF 에서는 그림이 표 위에 전체 폭으로 놓이고, 머리·하는 일·그림·표 첫 줄이 같은 쪽에 오도록 한다.
- 그림이 없는 화면은 그림 줄을 빼고 메모에 이유를 쓴다.

## 장면 카드 (스토리보드)

```
:::scene 장면 2 | 화면 9 문서 처리 현황
![문서 처리 현황 · 실패 행 펼침](shots/sb2_3.png)
누름: 실패 행 끝의 "열기"
그러면: 행 아래에 멈춘 단계와 원인, 할 수 있는 조치가 펼쳐짐
이후: (있을 때만) 그다음 이어지는 일
:::
```
- 그림 왼쪽, 누름·그러면 오른쪽. PDF 에서 한 쪽에 두세 장면이 들어가게 크기를 맞추고, 장면 하나는 쪽을 넘지 않는다.
- 흐름 절은 `:::steps` 로 순서를 먼저 보이고, 장면 뒤에 "갈라지는 경우 | 화면 반응" 표, 예외는 `:::callout warn 예외: …` 로 둔다.

## 검사에서 빠지는 글자

화면 문구를 그대로 옮길 때는 따옴표(“…”, "…", ‘…’, 「…」)나 코드(`` `…` ``)로 감싼다. 그 안의 글자는 문체 검사(AI 티, 평서형)와 대외 문체 금칙(화살표·절 기호)에서 빠진다. "◀ n / N ▶" 같은 화면 이름표가 그대로 통과한다. 경로·커밋·IP·PR 번호는 따옴표 안이어도 막는다.
