# report: 한국어 업무 보고서

**목표는 읽는 사람이 1분 안에 결론과 할 일을 아는 것이다.** 디자인은 `templates/report.css` 하나로 고정되고 원고에서 바꿀 수 없다. 글은 짧게, 표와 그림으로 보여 준다.

스크립트 경로는 이 스킬 폴더 기준이다(`<skill>/scripts/...`). 원고와 결과물은 사용자의 작업 폴더에 둔다.

## 1. 계약 잠그기 (한 줄로 말하고 바로 진행)

다섯 가지를 요청에서 추론해 사용자에게 한 줄로 알린다. 되묻는 것은 두 개 이상이 정말 불분명할 때 한 번만.

| 항목 | 값 |
|---|---|
| 종류 | progress(진행) · completion(완료) · qa(시험) · proposal(제안·결정 요청) · analysis(분석) · incident(장애) |
| 독자 | internal(팀 안) · external(고객사·외부). external 이면 대외 금칙 검사가 켜진다 |
| 결론 | 이 보고서로 독자가 알아야 할 한 가지와 해야 할 일 |
| 기준 | 수치의 기준(어느 서버·판·시점). `basis` 에 적는다 |
| 형식 | HTML 한 파일(기본). 산출물로 낼 때는 같은 HTML 을 `pdf.py` 로 A4 PDF |

예: "QA 보고 · 내부용 · 결론은 '결함 4건 모두 수정, 남은 확인 2건' · 기준 스테이징 서버 v1.4.2 로 쓰겠습니다."

## 2. 재료 모으기

- 사실만 쓴다. 숫자·날짜·이름은 출처에서 그대로 옮긴다. 없으면 지어내지 말고 `[확인 필요: 무엇]` 으로 둔다.
- 빈칸이 생기면 한 번에 표로 모아 사용자에게 알린다(완료 보고 3번).
- QA 는 캡처가 증거다. `scripts/capture.py` 로 찍거나 이미 있는 캡처를 쓴다(`references/qa.md`).

## 3. 원고 쓰기

1. `types/<종류>.md` 를 작업 폴더에 복사해 `<주제>_<YYMMDD>.md` 로 이름 붙인다. 틀의 절 순서를 지킨다.
2. `references/writing.md` 의 규칙대로 쓴다. 핵심 다섯 가지:
   - **첫 절은 결론.** 숫자 타일 2~4개 + 3줄 이내.
   - **절마다 표 하나 또는 5줄 이내.** 길어지면 표로 바꾼다.
   - **제목은 내용이 보이게.** "현황", "검토 결과" 같은 빈 제목 금지.
   - **선택지·중요도는 실제로 고를 게 있는 곳에만.** 모든 항목에 달지 않는다.
   - **수치에는 기준을 붙인다.** 어느 서버·언제·무엇 대비.
   - **말투는 개조식 명사형("수정 완료", "확인 필요"), 이어지는 문장만 "~습니다".** "~했다·~였다"는 쓰지 않는다.
3. 그림·표·상태는 `references/components.md` 의 블록으로 넣는다. HTML·style 을 원고에 직접 쓰지 않는다.

## 4. 다듬기 (산문이 많을 때만)

표와 개조식은 그대로 두고, 3문장 넘는 산문 문단이 있을 때만 그 문단을 `/humanize` (im-not-ai, light) 로 다듬는다. 윤문 뒤 숫자·고유명사가 바뀌지 않았는지 원고와 대조한다. 개조식을 문장으로 풀어 길게 만들면 되돌린다.

## 5. 검사와 빌드

```bash
python3 <skill>/scripts/check.py 원고.md            # external 이면 자동으로 대외 금칙까지
uv run --with markdown --with pillow python <skill>/scripts/build.py 원고.md -o 원고.html
uv run --with playwright --with pypdf --with pypdfium2 python <skill>/scripts/pdf.py 원고.html --pngs   # 산출물로 낼 때
```

- `check.py` 가 `READY` 가 될 때까지 원고를 고친다. ERROR 는 반드시, WARN 은 읽고 판단, GAP 은 사용자에게 알린다. 규칙을 느슨하게 바꿔 통과시키지 않는다.
- 빌드 결과를 1280px 과 390px 로 한 번씩 캡처해 직접 본다: 가로 넘침, 잘린 표, 캡처 크기, 빈 절. PDF 를 냈으면 `--pngs` 쪽 이미지도 본다: 표·캡처가 쪽 경계에서 잘리지 않았는지, 빈 쪽이 없는지. 고칠 것은 원고에서 고친다(CSS 를 만지지 않는다).

## 6. 완료 보고

사용자에게 넷만 말한다.
1. 결과 파일 경로
2. `check.py` 판정(오류·경고 수)
3. `[확인 필요]` 빈칸 목록과 내가 세운 가정
4. 화면 확인 결과. 캡처를 못 봤으면 "빌드 확인, 화면 미확인"이라고 쓴다

## 디자인을 바꾸고 싶을 때

색·글꼴·간격은 `templates/report.css` 한 곳에서만 바꾸고, 모든 종류의 예시를 다시 빌드해 확인한다. 보고서 하나만을 위해 스타일을 바꾸지 않는다.

## 쓰지 않는 경우

한 페이지 브리핑, 슬라이드, 엑셀·워드 파일 요청, 대화로 답하면 충분한 짧은 보고.
